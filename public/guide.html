Elsewhere / A considered starting point

A place to be found.

Your name. A little context. A few good links. Enough to help someone find what matters.

Elsewhere is a static profile template for people who want a home on the web without a whole publication to maintain. The example person is fictional; the sample links open service homepages, and the sample email uses example.com. Replace them before publishing your own page.

Small by choice.

Every destination has a readable name and a familiar link. The portrait is optional. Three links work as a short introduction; twenty work as a directory with clear groups. Everything stays visible and usable without JavaScript.

A restrained palette, generous spacing, and self-hosted Atkinson typography provide the starting point. Content and identity are yours. The template does not require a public credit, a particular platform, or a photo.

Make it yours.

  1. Copy starter.json into profile.json in the source package. Replace the name, bio, and links. Delete optional fields you don’t need.
  2. Choose a palette and accent, then set demo to false. This removes the example navigation and example pages from your build.
  3. Run npm run build with Node 22 or newer. Upload the contents of dist/ to a static host. No package installation or server runtime is needed.
{
  "name": "Your name",
  "bio": "A sentence about you.",
  "groups": [{
    "title": "Find me",
    "links": [{
      "label": "Your work",
      "url": "https://example.com"
    }]
  }],
  "appearance": {
    "palette": "paper",
    "accent": "blue",
    "theme": "system"
  },
  "demo": false
}

Options with a purpose.

You chooseThe template handles
Name, introduction, optional portraitWrapping, spacing, and a complete layout with or without an image
Links, order, groups, descriptionsReadable labels, optional destination details, and a single keyboard order
Paper or stone; blue, rust, or forestMatched light and dark colors, visible focus, and consistent contrast
System, light, or dark defaultA labeled visitor preference, enhanced when JavaScript is available

On a long directory, the Sections menu helps visitors jump to a group. It appears automatically with at least twelve links across three or more titled groups. Set sections to on to show it for any profile with at least two titled groups, or off to omit it.

For a portrait, add the file under public/assets/ and set portrait.src to its assets/… path. Use a short portrait.alt when the image adds information; leave it empty when it simply repeats the nearby name.

Interface labels and the favicon are configurable too. The source package includes complete customization and hosting guides. Jekyll is not required: upload the built files to a static host, or integrate them carefully alongside an existing blog.

The thinking behind it.

Function: help someone recognize you and choose a destination. Convenience: a small configuration, ordinary browser behavior, and files you can take anywhere. Aesthetics: proportion and care, without making people decode the interface.

This is influenced by Norman’s distinction between affordances and signifiers, Rams’s principles, and the approach developed in Quiet. The full rationale, alternatives, and research sources live in the source package’s docs/DESIGN.md.

Deliberate limits.

There are no accounts, analytics, feeds, social embeds, custom cursors, or third-party font requests in the template. Your host may still keep server logs. Editing JSON is less convenient than a hosted visual editor; that is the tradeoff for a small, portable site with no application service to maintain.

The accessibility target is WCAG 2.2 AA. Automated tests and browser inspection cover specific conditions; they do not establish universal accessibility. Screen-reader and physical-device testing are still needed before making a conformance claim. See docs/ACCESSIBILITY.md for the recorded scope.
